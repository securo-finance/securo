# Phase 12 Plan 01: v1.1 Integration & UX Adjustments

## Objective

- **What:** Close the remaining v1.1 milestone audit gaps and align the month guard UX with the intended product behavior.
- **Why:** Phase-local passes were not sufficient; milestone-level integration still had guard bypasses and an incomplete undefined-current-month browsing path.
- **Output:** Backend and frontend guard coverage is complete, closed-history browsing works without `Mês Atual`, and the dashboard month controls are consistent.

## Tasks

1. Fix the undefined-current-month dashboard path so users can enter closed snapshot view and keep using the shared month-state selector.
2. Enforce read-only or undefined-month guards on transaction bulk categorize, import, and recurring transaction entry points.
3. Allow category management without `Mês Atual` while preserving snapshot-mode read-only behavior.
4. Replace month inputs on the dashboard with one shared month/year picker interaction and update copy.
5. Extend automated coverage and update roadmap or requirements artifacts to match the shipped behavior.

- `npm --prefix frontend run build`
- `docker compose build backend && docker compose run --rm backend sh -lc "pip install --no-cache-dir -e '.[dev]' >/tmp/pip-phase12.log && pytest tests/test_months_api.py tests/test_transactions_api.py tests/test_recurring_api.py tests/test_import_api.py tests/test_categories_api.py tests/test_dashboard_api.py -q"`

## Success Criteria

- [x] Closed snapshots can be browsed even when `Mês Atual` is undefined.
- [x] Bulk categorize, import, and recurring transaction flows obey the editable-month guard contract.
- [x] Categories remain available without `Mês Atual`, but snapshot mode still blocks edit-oriented actions.
- [x] Dashboard month controls use one consistent month/year picker interaction and friendlier copy.
