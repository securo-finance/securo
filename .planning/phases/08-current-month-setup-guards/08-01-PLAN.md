# Phase 8 Plan 01: Current Month Setup and Guards

## Objective

- **What:** Add a first-class current-month status/API and enforce mutation guards until the active period is defined.
- **Why:** The monthly milestone cannot proceed safely if the app keeps defaulting to implicit date-based behavior and allows sync/manual entry before the user defines `Mês Atual`.
- **Output:** A reusable current-month contract in backend and frontend, plus guarded UI and API behavior for sync and manual creation flows.
