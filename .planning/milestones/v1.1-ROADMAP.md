# Milestone v1.1: Gestão Mensal

**Status:** ✅ SHIPPED 2026-04-04
**Phases:** 8-12
**Total Plans:** 5

## Overview

Flux moved from freeform period navigation to a monthly-control model centered on one editable `Mês Atual` plus preserved closed-month snapshots. The milestone delivered explicit month setup, durable period-linked records, close-month snapshot creation, protected-history navigation, and the final integration hardening needed to make the monthly workflow coherent.

## Phases

### Phase 8: Current Month Setup & Guards

**Goal**: Users can define the editable `Mês Atual` period and cannot perform sync or manual financial entry before that monthly context exists.
**Depends on**: Phase 7
**Plans**: 1 plan

Plans:

- [x] 08-01: Add current month API, dashboard setup flow, and mutation guards

**Details:**
- Introduced `/api/months/current` and a shared month-state contract.
- Blocked sync, account creation, transaction creation, transfers, and other guarded flows until `Mês Atual` exists.
- Added dashboard-first setup UX plus inline lock messaging across monthly-finance pages.

### Phase 9: Period-Linked Records & Cleanup

**Goal**: Users work with financial records that belong to a monthly period, without depending on legacy category-group concepts in supported flows.
**Depends on**: Phase 8
**Plans**: 1 plan

Plans:

- [x] 09-01: Persist monthly periods, link records, and remove category-group dependencies

**Details:**
- Added durable `monthly_periods` persistence.
- Linked accounts, manual transactions, sync imports, and file imports to monthly periods.
- Removed the supported category-group API/model/export surface.

### Phase 10: Month Closure & Next Month Start

**Goal**: Users can close the current editable month into a preserved snapshot and immediately continue with a newly opened `Mês Atual`.
**Depends on**: Phase 9
**Plans**: 1 plan

Plans:

- [x] 10-01: Add snapshot persistence and close-month workflow

**Details:**
- Added persisted `monthly_snapshots`.
- Implemented `/api/months/close` to close the active month and open the next editable month in one mutation.
- Extended dashboard month controls for month closure.

### Phase 11: Snapshot Navigation & Protected History

**Goal**: Users can move between `Mês Atual` and closed snapshots, understand when history is selected, and face confirmation before control-state changes on closed months.
**Depends on**: Phase 10
**Plans**: 1 plan

Plans:

- [x] 11-01: Add selected snapshot state, read routing, and read-only history protections

**Details:**
- Added app-wide selected snapshot context layered on top of the editable current-month state.
- Routed dashboard, accounts, transactions, and categories reads through snapshot context when active.
- Hardened primary mutation endpoints while a snapshot is selected.

### Phase 12: v1.1 Integration & UX Adjustments

**Goal**: Close the audit gaps in the monthly control milestone by fixing undefined-current-month snapshot browsing, enforcing all remaining month guards, and polishing the month selector UX.
**Depends on**: Phase 11
**Plans**: 1 plan

Plans:

- [x] 12-01: Close milestone audit gaps and align shipped UX behavior

**Details:**
- Enabled closed-snapshot browsing from the undefined-current-month state.
- Extended protected-history and undefined-month guards to bulk categorize, import, and recurring transaction writes.
- Kept categories available without `Mês Atual` as setup metadata while preserving snapshot-mode read-only behavior.
- Unified dashboard month/year picker behavior and later removed the extra visible next-month field in favor of a close-month modal flow.

## Milestone Summary

**Decimal Phases:**

- None

**Key Decisions:**

- Persist the active editable month as a first-class monthly-period record instead of implicit date defaults.
- Treat closed months as first-class snapshot records with explicit protected-history behavior.
- Keep categories available without `Mês Atual`, while continuing to block period-bound financial writes until the active month exists.
- Keep monthly lifecycle and history navigation in the existing Flux layout rather than introducing a separate surface.

**Issues Resolved:**

- Removed the remaining blocker-level gaps from the initial v1.1 milestone audit.
- Closed the supported runtime’s dependency on category groups.
- Added durable historical month navigation without sacrificing read-only protections.
- Fixed dashboard instability around month-state refreshes during account creation.

**Issues Deferred:**

- Nyquist validation artifacts are still missing for phases 08-12.

**Technical Debt Incurred:**

- Validation/process debt remains because `*-VALIDATION.md` artifacts were not created for the milestone phases even though Nyquist discovery is enabled.
