# Plan 02-01: Card-Scoped Transaction View

## Objective

Create a dedicated card detail route that shows only the selected card's imported transactions while preserving the core transaction-screen interaction model.

## Tasks

1. Add a `/cards/:id` route and load the selected connected credit-card account.
2. Reuse existing transaction APIs with a fixed `account_id` filter for the selected card.
3. Present the transactions in a familiar list with export, pagination, dialog inspection, and current-month guards.
4. Keep navigation context clear with card metadata and a return path to `/cards`.

## Verification

- Opening a card from `/cards` navigates to `/cards/:id`.
- The detail screen only shows transactions for that card's account ID.
- Familiar transaction interactions remain available where they are compatible with card-scoped browsing.
