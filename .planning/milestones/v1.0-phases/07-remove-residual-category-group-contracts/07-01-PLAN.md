# Phase 7 Plan 01: Remove Residual Category Group Contracts

## Objective

- **What:** Remove the remaining active category-group dependency from the supported category API contract and setup seeding path.
- **Why:** The milestone audit found that the user-facing flat category flow is still backed by a legacy `group_id` contract and default group seeding, which keeps `CAT-02`, `CAT-03`, and `MIG-04` open.
- **Output:** A flat category contract across API, setup, and shared frontend types, with regression coverage proving the shipped flow no longer revives category groups.
