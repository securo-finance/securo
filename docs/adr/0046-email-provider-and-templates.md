# 0046. The hosted instance picks the mail path, and an admin may rewrite the message

- Status: Accepted
- Date: 2026-11-25
- Origin: #554 (hosted release: a hosted instance has no SMTP server to point at, and a self-hoster wants the recovery message in their own words)
- Extends: [0004](0004-optional-capabilities.md), [0016](0016-outbound-calls-and-no-telemetry.md), [0044](0044-email-password-recovery.md)

## Context

ADR 0044 sends the recovery message over an SMTP relay the operator configures, with the text written into the code. A hosted instance has no relay of its own to give each customer, and an API that accepts a message over HTTPS removes the SMTP configuration from the picture entirely. Separately, the words of the message ("Securo", the tone, the extra sentence an organization wants) are the operator's, not the code's.

## Decision

- **The switch stays the only one.** `EMAIL_ENABLED` (ADR 0004) still decides whether anything leaves the instance and whether `POST /api/auth/forgot-password` answers `503`. `EMAIL_PROVIDER` only picks the path behind it: `smtp` (the default, ADR 0044) or `resend`. With the switch off, neither path is touched, whatever the provider says.
- **The hosted API.** `backend/app/services/email_service.py` posts `{from, to, subject, text}` to `RESEND_API_URL` (default `https://api.resend.com`) with `RESEND_API_KEY` in the `Authorization` header, over httpx. `send_email` dispatches on the provider; `deliver` keeps logging a refusal by class and numeric status only, so the token and the link never reach the log. Starting with the provider set to `resend` and no key, no `EMAIL_FROM`, no address, or an address that is not `https://`, refuses to boot: a half-configured provider failing at the first forgotten password is worse than failing at deploy. Those checks are the hosted provider's own: with `smtp`, `RESEND_*` is not read at all.
- **The message is the admin's, within bounds.** The templates live in `app_settings` under `email_templates` as JSON, one subject and one body per language, with the languages the message is written in today: `en` and `pt`. A language with no saved template keeps the built-in text, so saving one language never blanks the other. Allowed placeholders are `{app_name}`, `{link}` and `{minutes}`. The body must keep `{link}` exactly once, alone on a line of its own — it is the only way back into the account, and inside a sentence or wrapped in text the admin wrote, the text decides where the reader's click goes and the token inside it follows (`https://evil.example/c?u={link}`, `evil.example/{link}`). The subject may not carry it at all. Neither field may hold another address — a scheme (`https://`), a `www.` host or a bare host name (`evil.example`) all count, since a mail client turns the last one into a link too — and the check reads the message with the placeholders filled in, so an address assembled from the values counts as well (`reset{minutes}.com` is no address in the template and `reset60.com` is one in the message the reader gets). `{link}` stands for nothing while that last check runs, so an address typed into the text by hand is still found, even the sample one the check itself would put in its place. An unknown placeholder, an unbalanced brace, a conversion or format spec, an unknown language, an empty value, one past the length limit, a subject with a line break (a line break in a mail header makes every send fail) or a template breaking the link rule answers `400` with what is wrong and saves nothing. There is no free-form template language: `string.Formatter().parse` reads the placeholders and the set is closed.
- **A stored value that stops validating is ignored, not fatal.** If the row is edited by hand into something that no longer parses, `admin_service.get_email_templates` logs and falls back to the built-in text, so a mistake in the database cannot lock everyone out of their accounts.
- **The admin screen reads one endpoint.** `GET /api/admin/email` answers whether email is on, which provider, the sender and the effective templates; `PUT /api/admin/email` replaces the templates (an empty set clears them back to the built-in text) and answers the same shape. Both are superuser-only, like the rest of `/api/admin/`. The body is read from the request rather than through a model, so a broken template answers `400` with the reason instead of a schema error. The admin settings page shows the state, marks the provider and sender as read-only (they come from the environment) and lets an admin edit the English and Portuguese templates.
- **Outbound call** (extends ADR 0016): with `EMAIL_PROVIDER=resend`, a message is posted to the configured API host, only with `EMAIL_ENABLED` on and only when someone asks for a recovery link.

## Consequences

- A hosted instance sends without any SMTP configuration; a self-hoster keeps their relay and sends nothing anywhere else.
- The placeholders are a closed set: a new one (a support address, say) is a code change with a default value, not a template edit.
- Only `en` and `pt` can be customized, matching the languages the built-in text exists in. Other readers get English, as before.
