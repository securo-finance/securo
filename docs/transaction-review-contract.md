Transaction review policy PATCH contract

PATCH /api/workspaces/{workspace_id} remains owner-gated and replaces review_policy; it does not merge a partial dictionary. Omitted keys in a replacement use effective defaults (ingest=needs_review, manual=reviewed); null resets the policy to those defaults.

Any request containing review_policy, including null, must also contain expected_review_policy with exactly both ingest and manual, each needs_review or reviewed. Under a fresh workspace row lock, the server compares that complete expectation against the effective persisted pair. Request-model validation returns HTTP 422 for nonobject expectations (string, array, number or boolean). Transport-valid but missing, null, incomplete, invalid-effective-key/value or stale dictionary expectations return HTTP 409. With a valid current expectation, a schema-valid replacement containing unknown policy keys/values returns HTTP 400; schema-invalid replacement types return HTTP 422. Every rejection precedes bundled workspace settings and acting-user currency preference writes. expected_review_policy is transport-only, never persisted. Requests omitting review_policy preserve the previous client contract and need no expectation.

Clients must send a complete draft replacement and complete baseline expectation. On 409 retain local edits, refresh and reconcile per key against baseline/draft/server; never automatically resubmit. A failed same-auth refresh retains the last usable workspace and local draft, displays a safe error and blocks policy re-save until a successful refresh reconciles it. Auth identity changes/logout discard cached workspace state and mounted drafts, and late prior-auth responses are ignored. A clean key adopts server; a locally edited key stays when server equals baseline; convergence accepts server. With this closed binary value domain a three-distinct-value conflict is impossible; do not invent a third state to test conflict. An intervening actual server write is still rejected by the request precondition. Local edits made during a save survive acknowledgement, keyed by edit generations; workspace switching and superseded refreshes cannot apply old responses to a new draft.

Existing transaction review writers lock their full affected write set in transaction-ID order before transition decisions, then freshly populate clean ORM state. A pre-existing dirty target is rejected with 409 and rollback rather than autoflushed or refreshed away. Generic PATCH discovers anchor/series/actual transfer cascades/series-total writers as one union, revalidates membership after locking, and conflicts rather than expanding to an unlocked row. Review remains anchor-only in scoped edits. set_review_status remains query-free for transient/initial/detached semantics. Rule-only reruns preserve all five provenance fields; apply_all_rules retains its inherited matched-or-changed count, which may be 1 on a no-op, while apply_single_rule and bulk updated count actual changes.

Review-status rule condition values alone canonicalize surrounding whitespace and case on schema/storage round trips and engine matching, including legacy stored literals; generic text rules keep their whitespace semantics. Review-filtered lists never expose a partial-ledger running balance.
